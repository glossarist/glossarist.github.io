## Project Overview

Glossarist.org is the website for [Glossarist](https://github.com/glossarist), open-source software for maintaining multi-language concept systems. Built with **Astro 7**, Vue 3 islands, and TypeScript.

## Build & Development Commands

- `npm run dev` — Astro dev server with hot reload
- `npm run build` — Production build (output to `dist/`)
- `npm run preview` — Preview production build locally
- `npm test` — Run Vitest suite
- `npm run test:coverage` — Run tests with coverage report

Uses **npm** with `"type": "module"`.

### Content organization

Content lives in `src/content/` organized into four Astro Content Collections:

- `blog` — Blog posts (`title`, `date`, `authors`, `description`)
- `docs` — Documentation (`title`, `description`)
- `reference` — Reference pages (`title`, `description`, `fullscreen`)
- `pages` — Top-level pages like `about.md` (`title`, `description`)

The collection schemas are defined in `src/content.config.ts` and validated at build time.

### Sidebar navigation

Per-section sidebars configured in `src/data/sidebars.ts`. Each docs section has its own sidebar. The Software nav dropdown is auto-generated from `src/data/projects.ts`.

### Vue islands (hydration strategies)

- `client:load` — Hydrate immediately (HomePage, ModelLanding)
- `client:visible` — Hydrate when scrolled into view (OntologyBrowser, SchemaReference, YamlSchemas, RelationshipTypes)
- `client:idle` — Hydrate when browser is idle (ReleaseDownloader)
- (no directive) — Static, server-rendered only

### Custom components

- `ReleaseDownloader` — Client-side fetch of latest GitHub release via REST API, with localStorage caching (1h TTL) and OS detection from `navigator.userAgent`
- `HomePage` — Hero section, software cards grid (driven by `projects.ts`), "used by" section, features grid
- `OntologyBrowser` — Interactive OWL ontology browser; reads `/data/ontology-schema.json` via `useOntologyData` composable
- `SchemaReference` — SHACL shapes table; reads `src/data/schemas-bundled.json`
- `RelationshipTypes` — 52 relationship types with categories, inverse pairs, alphabetical reference; reads `/data/taxonomies.json`
- `ModelLanding` — Marketing landing for the model docs section
- `LogoMerge` — Animated SVG showing cultural roots of the Glossarist logo

### Styling

CSS custom properties for brand colors (`--glossarist-primary`, `--vp-c-brand-*`). Dark mode via `.dark` class on `<html>`, toggled by `localStorage['vitepress-theme-appearance']`. All in `src/styles/custom.css`.

### Search

Pagefind index generated at build time in `dist/pagefind/`. Search UI wired into `Nav.astro`.

### Images

Static images live in `public/images/`:
- `desktop/` — Screenshots for desktop app docs
- `model/` — UML diagrams from concept-model repo

## Build pipeline

`npm run build` chains:
1. `node scripts/generate-ontology-data.mjs` — TTL → JSON taxonomies
2. `node scripts/generate-ontology-schema.mjs` — Ontology schema JSON
3. `node scripts/copy-schemas.mjs` — Copy YAML schemas from concept-model
4. `node scripts/bundle-schemas.mjs` — Bundle schemas into `src/data/schemas-bundled.json`
5. `astro build` — Astro static build

All scripts are framework-agnostic — they read from `concept-model/` (cloned in CI) and write to `public/data/` (or `src/data/`).

## Testing

Vitest with jsdom environment. Tests in `test/`:
- `test/format.test.ts`, `projects.test.ts`, `standards.test.ts` — Data utilities
- `test/useOntologyData.test.ts` — Vue composable with mocked fetch
- `test/scripts.test.ts` — Integration tests on build output JSON shapes
- `test/components/*.test.ts` — Vue component tests (full coverage on simpler components, smoke mounts on heavier ones)

Coverage: `npm run test:coverage`.

## Deployment

GitHub Actions workflow (`.github/workflows/build.yml`):
- Triggers on push to `main` branch
- Checks out this repo + concept-model repo (data source)
- Node 24, `npm ci && npm run build`
- Uploads `dist/` via `upload-pages-artifact@v4`
- Deploys to GitHub Pages via `deploy-pages@v4`
- Link checker via lychee on every build
